BasketBoss — Google sign-in setup
22 November 2026

The app integration is prepared for web, iOS and Android. The owner reports completing the Google Web client and Supabase Google-provider setup. Those console settings have not been independently verified. Until the public provider settings report Google enabled, the Google button stays hidden and existing Apple/email sign-in remains available.

1. Google Cloud — choose or create the BasketBoss project
Open https://console.cloud.google.com/auth/overview
Use Google Auth Platform (the Google sign-in service).
Set the app name to BasketBoss and complete the support/developer contact fields.
App homepage: https://basketboss.co.uk
Privacy policy: https://basketboss.co.uk/privacy
Terms: https://basketboss.co.uk/terms
Use an External audience for a public consumer app. While Testing, add your Google account and each test user's actual Google address under Test users.
Use the basic sign-in scopes: openid, email and profile. No Gmail, Drive or billing API permission is needed for this login.

2. Create the OAuth client
Google Auth Platform → Clients → Create client → Web application.
Suggested client name: BasketBoss sign-in.
Authorized JavaScript origins:
  https://basketboss.co.uk
  https://www.basketboss.co.uk
Authorized redirect URI — copy EXACTLY:
  https://kbhyosxuvlcazyzzinqv.supabase.co/auth/v1/callback
Save the Client ID and Client Secret in your Google/Supabase consoles. Do not paste the secret in chat or add it to the app repository.
The current implementation uses a system-browser OAuth flow on mobile, so it uses this Web client; no Google native SDK, iOS reversed-client scheme, Android signing fingerprint or extra Play Billing product is needed for this integration.

3. Enable Google in Supabase
Open https://supabase.com/dashboard/project/kbhyosxuvlcazyzzinqv/auth/providers
Find Google, enable it, paste the Web Client ID and Client Secret, then save.
Keep existing Apple/email settings and nonce/security defaults.

4. Check Supabase return URLs
Open https://supabase.com/dashboard/project/kbhyosxuvlcazyzzinqv/auth/url-configuration
Keep existing Site URL and redirect entries. Add these exact return URLs if missing:
  https://basketboss.co.uk/app?bb_auth=google
  https://www.basketboss.co.uk/app?bb_auth=google
  basketboss://auth/callback?bb_auth=google
  basketboss://auth/callback?bb_auth=signup
  basketboss://auth/callback?bb_auth=recovery
The signup and recovery entries support the existing native email-confirmation/password-recovery flows. Keep the existing website wildcard entries. Native Apple sign-in uses the existing ID-token flow and does not need an Apple URL added here.
The custom basketboss:// URL belongs in Supabase's redirect allowlist. Google's Web client uses the HTTPS Supabase callback from step2.

5. Test using the updated app source/build
Reload/relaunch after enabling the provider. Open Save your personalised plan or Account → Continue with Google.
- New user: verified Google sign-in returns to Offer with feeding/goal choices retained.
- Returning user: Sign in from Welcome goes directly to Plan.
- Cancel/deny: stays signed out with choices retained, and retry works.
- Check that an existing membership still loads from the same verified BasketBoss account; login alone never grants Premium.
- For a new-account test use an actual second Google account. Gmail +aliases are email aliases, not separate Google accounts.
- Existing restore/subscription management still uses the original platform handlers.
New native builds are required to include this source change. Use the new iOS Build 61 and Android 1.0.8 / code 8 release launchers. Earlier Build 60 / Android code 7 commands remain pinned to older source and do not include Google sign-in.
If Google Auth Platform Audience is still Testing, add each real testing Google account under Test users before testing. Review production audience/branding requirements before offering Google sign-in publicly.

6. Password and deletion compatibility
Google verifies sign-in, so a new Google-only user need not type a BasketBoss password to log in.
The existing deletion guard still requires a separate BasketBoss password for non-Apple accounts. Account now includes Set a BasketBoss password: it opens the original email recovery flow, then the existing verified password-update flow. After setup, that BasketBoss password can be used in the unchanged deletion form. Never enter your Google password there.
Accounts linked to Apple retain the existing Apple confirmation/revocation requirement.
A direct Confirm with Google & delete flow is not part of this change; it would require separate server reauthentication work.

Release status
Application source and local intercepted tests are prepared; actual Google/device acceptance is still required on the new builds. This setup document does not change Google/Supabase settings, schema, billing/deletion endpoints or store submissions. The owner reports making the console settings manually.
