## Autofill

`bb-recipe-planning.js` derives protein, cheese-heavy and dinner eligibility metadata, with explicit overrides on new records. Rotation history is scoped to the account and persists across tier changes. Only the whole currently accessible dinner pool can trigger a cycle reset; narrow category/time filters cannot reset it. Dessert, baking and breakfast records are excluded.

Proposals reserve recipes in memory. Rotation commits only after user confirmation and a successful plan save; cancellation consumes nothing. Failed history persistence rolls the plan back. Consecutive days cannot use the same normalized primary protein, and the seven-day plan allows at most two cheese-heavy dinners. Existing manual plans are preserved; an incompatible existing plan must be adjusted before autofill can add to it.

Automatic linked batch nights conflict with the strict consecutive-protein rule, so they are not generated by varied autofill. Per-recipe manual batch cooking remains available. Saturday date-night recipes are a preference within the unseen pool, rather than a filter that can strand other dinner recipes.
