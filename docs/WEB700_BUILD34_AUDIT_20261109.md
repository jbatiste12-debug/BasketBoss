# BasketBoss web catalogue 700 and iOS build 34 audit

Review date: 9 November 2026. This document records the prepared changes; it does not certify a production deployment or App Store release.

## Scope and compatibility

The web/PWA and next iOS 1.0.2 client use 700 recipes: 200 Free, 500 Premium and 50 breakfast options overall. Breakfast selection remains optional and separate from dinner Auto-Fill. Build 34 corrects the actual 200-ID Free allowlist and the independent Make a Meal loader. Build 33 must not be used for this combined release.

Legacy recipe objects, IDs, positional ingredient arrays, root 100-Free files and old Premium endpoints remain protected. Generated `/pwa700` documents and the dedicated native generator provide the expanded catalogue separately. Paid data still requires the authenticated versioned API; it is excluded from public files and service-worker caches. The frozen data release remains `catalogue700-20261108-build33`; its approval hashes and protected 400-row hash are unchanged.

Landing, pricing, comparison and PWA copy distinguish the expanded web collection from the currently published iOS catalogue. Prices retain their existing billing rules; grocery figures remain estimates rather than verified live shelf prices.

## Interaction and performance changes

- Pantry selection supports long press, multiple foods, visible-item selection, cancellation and a named-item deletion confirmation. It delegates to existing stock removal and one guarded save; failure, stale stock and account changes are checked. Household essentials and meal plans are excluded.
- Generated 700 clients omit an unused whole-catalogue fallback-rate scan. Selected-ingredient pricing still runs normally; no plan, account or stock result is cached.
- Pantry readouts share requirements within one read/proposal. Hidden editor controls are built when needed. Independent edits and later proposals obtain fresh requirements.
- US presentation writes avoid equal-text DOM mutations. Weekly calculations reuse bounded time-zone formatters, while dates, week results and US device-zone reads remain fresh.
- Keyboard continuity preserves the intended planner/Cook control through rerenders without moving pointer focus or scrolling.
- Cook mentor speech starts at a completed first sentence and prefetches one following native clip. Provider, entitlement, quota and playback protections remain intact.

Controlled mentor fixtures measured first audio at 1089→274 ms and 1105→286 ms; a synthetic native inter-clip gap fell from 180→0 ms with the same two synthesis requests. These are local test results, not production latency guarantees. Final controlled three-dinner checks measured pantry editing at 203–234 ms, save at 650 ms and deletion at 536 ms; opening At home with 31 foods remained 871–940 ms. These are improvements, not an instant-action guarantee. Auto-fill now paints its busy state before computation; final Free/Premium checks preserved saved dinners and changed only the requested day.

## Verification and release gates

Completed focused checks include 22 Chromium keyboard cases, 16 pantry transaction cases, 29 client/PWA/routing checks and five public deployment-verifier tests. The PostgreSQL/Chromium CI workflow requires pinned test engines, deterministic PWA regeneration and the complete regression suite. Main additionally checks deployed public assets, routing, images, legacy Free100 and anonymous Premium denial without customer credentials.

The complete local suite passed: 3,288 passed, zero failures, one existing Swift/Linux skip and two existing Paddle TODOs. Chromium and PostgreSQL tests ran. The final native public package verified 1,147 files with exactly 200 Free recipes and no private recipe bundle. macOS archive/StoreKit/keyboard CI and the read-only production verifier remain required release gates. Physical-iPhone subscription testing and signing/upload remain release checks on the Mac; both initial subscriptions must accompany the app's review submission.
