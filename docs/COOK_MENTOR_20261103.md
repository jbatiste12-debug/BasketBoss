# Chef Boss cooking mentor

This extends Voice Cook into a Premium conversation about the active recipe. Users can ask spoken or typed cooking questions, ask follow-ups, and hear short replies in a warm British mentor voice. The default companion name is **Chef Boss**; a bounded custom name is saved on the current device for the signed-in account. Starting Cook shows a named greeting, and speaks it when voice is already enabled. Starting Cook alone never requests microphone access.

The client sends the active recipe, displayed serving amounts, method, cooking position, region and up to six in-memory turns to the protected `/api/cook-assistant` endpoint. It uses the existing verified Premium/session/deletion checks and server-owned OpenAI Responses settings with `store:false`. The AI returns answer text only. Navigation and timers still require explicit local commands; model output cannot perform app actions. Ingredient amounts and regional display remain those shown in Cook, with US conversion restricted to the American region.

Mentor speech uses the server-owned Marin profile through `/api/tts` with `private:true`. Personalised speech is generated without R2, a shared cache or persisted chat history. Browser audio and native MP3 bytes stay temporarily in memory. The native bridge holds its speech ticket until playback finishes and clears playback on cancellation, account changes, backgrounding or departure from Cook. The mentor does not silently substitute the device voice. If natural audio is unavailable, its answer remains readable with a clear retry control.

The existing Cedar recipe-narration API remains available to build 4. A separate production hotfix corrects unsupported Cloudflare provider redirect handling. That server fix does not add conversation to build 4: the new mentor controller, open dictation and in-memory audio playback require **iOS 1.0 (5)**.

Both conversation and private speech retain the configured daily bounds (currently 80 per member/household owner and 200 across the site), using separate `cook-assistant` and `cook-tts` usage actions. No additional SQL tables or provider credentials are required. Questions, conversation history and personal mentor audio are not saved by BasketBoss; provider processing remains subject to OpenAI's terms, as disclosed in Cook and the privacy policy.

Portable checks cover the real client/server contract, auth, quotas, deletion races, safe failures, cancellation and uncached audio. Actual mobile WebView QA requires all 41 Cook/voice/mentor flags, including named greetings and follow-ups. Stubbed QA establishes UI/control behaviour, not audible naturalness. Mac compilation and physical-iPhone listening must be verified before describing the release as fully tested. No signed Apple upload has been performed by this workspace.
